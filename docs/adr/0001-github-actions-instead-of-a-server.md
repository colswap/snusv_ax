# 0001. 상시 서버 대신 GitHub Actions

- 날짜: 2026-08-13
- 상태: 채택

## 맥락

회계 리마인더를 어디서 돌릴지 정해야 했다. 후보는 상시 서버(Fly.io·Railway·개인 서버)에 Socket Mode로 붙는 방식과, GitHub Actions cron으로 하루 한 번 스크립트를 돌리는 방식이었다.

"슬랙봇"이라는 말이 상시 떠 있는 서버를 떠올리게 하지만, 실제로 필요한 것은 하루 한 번 도는 작은 스크립트다.

## 결정

GitHub Actions cron을 쓴다. 서버를 두지 않는다.

## 근거

**실시간이 아무 가치를 주지 않는다.** 판정 기준이 "48시간 경과"이므로 이벤트를 즉시 받아봐야 할 일이 없다. 상시 서버의 유일한 장점이 이 봇에서는 0이다.

**서버는 관리자를 요구한다.** 매년 운영진이 바뀌는 조직에서 "이 서버를 계속 살려둘 사람"은 자동화가 죽는 가장 흔한 원인이다. Actions는 레포 소유권만 넘기면 인수인계가 끝난다.

**자동화가 늘어날 때 격리가 공짜다.** 서버에 여러 자동화를 얹으면 하나가 죽을 때 같이 죽고, 따로 띄우면 서버가 늘어난다. Actions는 워크플로가 독립이라 이 문제가 없다.

**비용이 0이다.** 퍼블릭 레포의 Actions는 무료다.

## 결과

- 스케줄 지연이 몇 분 발생할 수 있다. 하루 한 번 요약이라 무관하다.
- 퍼블릭 레포의 60일 비활성화 규칙에 걸린다. `keepalive.yml`로 대응한다. → [0004](0004-keep-the-slack-app-internal.md) 및 RUNBOOK 참조
- 슬래시 명령어·버튼 같은 즉각 반응 기능은 못 쓴다. 필요해지면 그때 다시 판단한다.
