# 0005. 기성 도구 대신 직접 만든다

- 날짜: 2026-08-13
- 상태: 채택

## 맥락

"이 정도는 이미 누가 만들어놨을 텐데 재발명 아닌가"는 정당한 질문이고, 처음에 물었어야 했다. 뒤늦게 조사한 결과를 남긴다. **다음에 같은 의문이 들면 이 문서를 먼저 읽고, 그때는 시장 상황이 바뀌었을 수 있으니 날짜를 확인하라.**

## 구조적 제약: "체크가 없다"는 이벤트가 아니다

Slack Workflow Builder의 트리거는 다음이 전부다.

> 링크에서 · 웹훅에서 · 스케줄로 · 리스트 항목 변경 시 · 메시지 게시 시 · 채널 참여 시 · 이모지 리액션이 사용될 때

"리액션이 **달릴 때**"는 있지만 "리액션이 **없을 때**"는 없다. 있을 수 없다 — 일어나지 않은 일은 이벤트가 아니기 때문이다. Zapier와 Make도 마찬가지로 이벤트 트리거 기반이라 부재를 감지하지 못한다.

따라서 이 문제는 반드시 ①주기적으로 깨어나 ②히스토리를 읽고 ③리액션 유무를 검사하는 폴링을 요구한다. **노코드 도구로는 구조적으로 풀리지 않는다.**

## 검토한 오픈소스

| 저장소 | 판정 방식 | 실행 | 결론 |
|---|---|---|---|
| `albznw/slack-reaction-bot` | 리액션 없는 사람 찾기 | **온디맨드** (사람이 명령) | 사람이 기억해야 하므로 원래 문제를 못 푼다 |
| `openforcefield/slack-triagebot` | **본문 텍스트 속** 이모지 | 슬래시 커맨드 | 리액션이 아니라 텍스트를 본다 |
| `slack-samples/deno-triage-bot` | ⚪🔵🔴로 **시작하는** 메시지 + 👀/✅ 리액션 | 스케줄 | 아래 참조 |

**`deno-triage-bot`이 가장 근접했다.** Slack 공식 샘플이며 스케줄 리포트와 ✅ 리액션 기반 상태 추적을 한다. 우리 설계가 Slack이 권장하는 패턴과 같다는 방증이기도 하다.

그럼에도 채택하지 않은 이유:

1. **요청 식별이 접두어 이모지에 의존한다.** [0003](0003-no-automatic-classification-filter.md)에서 실데이터로 기각한 방식이다. 형식을 안 갖춘 급한 요청이 먼저 누락된다.
2. **Slack 유료 플랜이 필수다.** 무료 워크스페이스는 workflows/functions를 지원하지 않는다. 우리 구현은 일반 Web API만 쓰므로 플랜과 무관하다.

## 검토한 상용 도구

Slack 티켓팅 도구(ClearFeed·Unthread·Thena 등)는 SLA 타이머와 에스컬레이션으로 이 일을 실제로 해낸다. ClearFeed는 이메일→Slack까지 포함해 두 자동화를 한 번에 덮을 수 있다.

| 도구 | 무료 티어 | 유료 |
|---|---|---|
| Suptask | **월 10티켓** | — |
| Enjo | AI 답변 200회/월 | $95/월~ |
| Thena | 없음 | $29/유저/월~ |
| ClearFeed | 없음 (14일 체험) | $24/에이전트/월 |

**무료 티어는 전부 볼륨에서 탈락한다.** 회계만 월 30건이고 메일은 월 600건인데, 가장 넉넉한 무료 한도가 월 10티켓이다.

유료는 4명 기준 연 $1,150 수준이다.

## 결정

직접 만든다.

## 근거

**구현 규모가 작다.** 판정 70줄, 렌더링 40줄, 공통 부품 180줄로 300줄이 안 된다. 300줄을 위해 연 $1,150은 과하다.

**핵심이 조직 고유 규칙이다.** 기수 경계, ❌ 수동 제외, 본인 글에 본인 체크 허용 — 전부 실데이터에서 나왔고 어떤 기성품도 그대로 맞지 않는다.

**SaaS는 사라진다.** Slack 티켓팅의 대표 주자였던 **Halp은 2024년 6월 서비스를 종료**했다. Atlassian이 인수해 Jira Service Management로 흡수했고 기존 고객은 마이그레이션해야 했다. 매년 운영진이 바뀌는 조직에서 "3년 뒤 도구가 없어지면 누가 옮기나"는 실재하는 비용이다.

**인수인계가 더 쉽다.** SaaS는 계정과 결제수단 이전이 필요하다. 학생 조직에서는 레포 소유권 이전보다 어렵다.

## 결과

- 코드를 우리가 유지보수해야 한다. 300줄이고 판정 로직이 순수 함수라 감당 가능한 수준으로 설계했다.
- Slack 무료 플랜에서도 동작한다. 유료 플랜을 요구하는 대안 대비 이점이다.
- **이 판단은 규모에 묶여 있다.** 자동화가 10개로 늘거나 판정 규칙이 훨씬 복잡해지면 다시 계산해야 한다. 그때는 이 문서의 표를 최신 가격으로 갱신하고 판단하라.
